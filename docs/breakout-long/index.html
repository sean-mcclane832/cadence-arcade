BREAKOUT, 10X LONGER

Same game, players and protocol as One-Frame Breakout, but each life trains for 300 blocks (300,000 moments) instead of 30. 12 seeds per player. cadence-net 0.89.0.

The first run stopped while every curve was still climbing. So: what happens if you just keep going?

What it showed

  • Cadence keeps learning. All three Cadence brains more than doubled after block 30 and were still rising at block 300.
  • One frame is a wall for a plain learner, not for Cadence. The one-frame MLP flattens near 6 bricks: it can't tell which way the ball is moving. Every Cadence brain beats it on 12 of 12 seeds, by about 7 bricks. A follow-up probe found why: Cadence wires in a working-memory copy of the last frame by default, so it has the ball's direction built in, not learned.
  • Handing the MLP the second frame wins in the long run. At 30 blocks it was level with Cadence. By 300 it leads every Cadence brain (12/12 vs the position-term brain, 11/12 vs no-recall), about 6 bricks ahead. The probe says Cadence has nearly the same information (direction readable at 98% vs 99%), so the gap is in how it learns to use it.
  • The 0.89.0 position term: null, confirmed. On these 12 seeds it looked like +3 bricks (7/12, p = 0.09), so we ran 24 more seeds. Pooled over 36 seeds it wins 17, median -1.0 bricks, p = 0.68. The lean was noise. Recall memory with or without it doesn't beat having no recall at all.

How it ran

One command on a desktop CPU, about 30 minutes per Cadence life and 3 per MLP life, 6 at a time: run.py --seeds 10-21 --arms pos32,pos0,norecall,mlp1,mlp2 --blocks 300 --procs 6 --out runs/long10x. Nothing else changed from the pre-declared protocol in run.py. Raw lives in runs/long10x.
